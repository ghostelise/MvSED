Streaming social event clustering

Latency-Aware Selective Multi-View Retrieval for Unsupervised Event Clustering

MvSED fixes candidate membership with text retrieval, invokes auxiliary views only for uncertain decisions, and accepts a repair only when a frozen label-free evidence gate agrees.

System overview

A short critical path for streaming decisions

Confident assignments bypass auxiliary reasoning. Only uncertain primary outputs enter a bounded residual path, and only resolved events update memory for subsequent anchors.

Method

One controlled protocol, three connected stages

The method separates the shared inference unit from the proposed retrieval and repair mechanisms, making every comparison auditable.

01

Shared protocol

Fixed single-stage anchors

Messages are embedded and grouped once with a fixed threshold. Representative messages preserve coverage while controlling redundancy.

  • Shared anchor settings within each paired panel
  • No second-stage anchor reclustering
  • Event2018: matching ordered anchor hashes
  • Event2012: equal counts; legacy ordered hashes incomplete

Inherited from RagSEDE · Section 3.1

At most 100 messages and three representatives per anchor. Anchor thresholds are 0.40 for Event2012 and 0.30 for Event2018.

Event memory stores names, keywords, linked anchors, representative messages, and time observations.

02

Core retrieval

Text-grounded selective MVRA

Text retrieves the only admissible candidate pool. Entity, relation, and temporal evidence can rerank that pool, but cannot introduce new candidates.

  • Relevance-minus-redundancy view selection
  • Bounded auxiliary-view budget
  • Text-majority score fusion
03

Residual decision

Uncertainty-gated repair

Only Others or Confusion assignments enter repair. A frozen label-free gate changes the result when semantic, structural, confidence, and margin evidence agree.

  • Confident decisions remain unchanged
  • Temporal evidence cannot justify repair alone
  • A rejected repair preserves the primary result
  • Others follows novelty creation; Confusion remains abstention
  • Only resolved events update memory

Abstract

Bounded evidence for timely monitoring

Streaming social-event monitoring requires bounded end-to-end latency, yet remote-LLM failures and retries create long critical paths. We propose MvSED, which minimizes time-to-memory-commit under a clustering-quality constraint rather than token count. Text fixes candidates, relevance–redundancy selects rerankers, and a frozen label-free gate repairs only uncertain assignments. Across two benchmarks, MvSED reduces wall-clock latency by up to 22.3%, preserves Event2012 clustering quality, and improves Event2018 ARI by 0.0567. Latency falls despite higher token counts, confirming that tokens are an unreliable proxy for end-to-end efficiency. Code: ghostelise.github.io/MvSED.

Reporting boundary

What the evidence supports

Remote load makes latency deployment-specific. Quality intervals include zero, and other social platforms remain untested. Labels are used only for development and post-hoc evaluation, never for test-time decisions.
