System overview

A short critical path for streaming decisions

Confident assignments bypass auxiliary reasoning. Only uncertain primary outputs enter a bounded residual path, after which the final assignment updates memory for subsequent anchors.

Method

One controlled protocol, three connected stages

The method separates the shared inference unit from the proposed retrieval and repair mechanisms, making every comparison auditable.

01

Shared protocol

Fixed single-stage anchors

Messages are embedded and grouped once with a fixed threshold. Representative messages preserve coverage while controlling redundancy.

  • Identical ordered anchors across paired methods
  • No second-stage anchor reclustering
  • Hash-based audit before a run is admitted
02

Core retrieval

Text-grounded selective MVRA

Text retrieves the only admissible candidate pool. Entity, relation, and temporal evidence can rerank that pool, but cannot introduce new candidates.

  • Relevance-minus-redundancy view selection
  • Bounded auxiliary-view budget
  • Text-majority score fusion
03

Residual decision

Uncertainty-gated repair

Only Others or Confusion assignments enter repair. A frozen label-free gate changes the result when semantic, structural, confidence, and margin evidence agree.

  • Confident decisions remain unchanged
  • Temporal evidence cannot justify repair alone
  • Final decisions update dynamic event memory

Abstract

Bounded evidence for timely monitoring

Streaming social event monitoring requires timely event assignments. Existing retrieval-augmented detectors rely on text queries or invoke multiple evidence views unconditionally, causing query drift and long remote-LLM critical paths. We propose MvSED, which treats multi-view evidence as a bounded residual correction. Text retrieval fixes candidate membership, relevance–redundancy selection chooses rerankers, and a frozen label-free gate accepts only consistent repairs of uncertain assignments. On Event2012, MvSED yields mean NMI, AMI, and ARI changes of +0.00023, +0.00005, and +0.00069, while reducing runtime and LLM calls by 11.3% and 1.3%. On Event2018, the corresponding mean changes are +0.0098, +0.0127, and +0.0567, with runtime and calls reduced by 22.3% and 5.9%. Although Event2018 tokens increase by 11.9%, failed attempts fall by 53.7%, exposing a practical latency–token trade-off.

Reporting boundary

What the evidence supports

Remote load makes latency deployment-specific. Quality intervals include zero, and other social platforms remain untested. Labels are used only for development and post-hoc evaluation, never for test-time decisions.
